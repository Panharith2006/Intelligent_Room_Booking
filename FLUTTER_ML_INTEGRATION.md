# Flutter ML Integration for Room Booking System


### Device (Android/iOS/emulator):

#### Target Devices:
- **Primary**: Android devices (API 21+)
- **Minimum Android Version**: Android 5.0 (Lollipop)
- **Recommended**: Android 8.0+ (Oreo)

#### Testing Devices:
1. **Physical Device**: 
   - Any Android phone running Android 5.0+
   - USB debugging enabled
   
2. **Emulator**: 
   - Android Studio AVD (Android Virtual Device)
   - Recommended: Pixel 5 API 33 emulator
   - RAM: 2GB+
   - Storage: 4GB+

#### Device Requirements:
- **Internet Connection**: Required for API calls to Django backend
- **Storage**: ~50MB for app installation
- **RAM**: Minimum 2GB

---

### Model (Prebuilt/Custom + File Format):

#### Language Model (Backend):
- **Model Name**: gemma3:1b (Google's Gemma)
- **Type**: Prebuilt, fine-tuned for conversations
- **Size**: ~1GB
- **Format**: GGUF (GPT-Generated Unified Format)
- **Hosting**: Local via Ollama on Django server
- **Access**: Via REST API (no direct model access from Flutter)

#### Flutter Side:
- **No local ML model required** - all inference happens on backend
- Flutter app only handles:
  - UI/UX
  - HTTP requests
  - Response parsing
  - Chat history management

#### RAG Data Sources:
1. **System Knowledge Base**:
   - File: `SYSTEM_KNOWLEDGE_BASE.md`
   - Contains: Room details, booking policies, FAQs
   - Format: Markdown text
   - Embeddings: Generated by Semantic Kernel

2. **Dynamic Data** (from Django database):
   - Rooms table (room details, capacity, features)
   - Bookings table (availability, schedules)
   - Users table (departments, faculties)
   - BookingRules table (policies, restrictions)

#### Vector Store:
- **Type**: In-memory vector store (Semantic Kernel)
- **Embeddings**: Generated from knowledge base documents
- **Purpose**: Semantic search for relevant context
- **Updates**: Dynamic, refreshes with database changes

#### Chat Data:
- **User Messages**: Collected from Flutter app
- **Session Management**: Cached in Django (Redis/Memcached)
- **History**: Stored locally on device using Hive
- **Privacy**: User data stays on backend, not used for training

## 5) API Endpoints for Flutter Integration

### Base URL:
```
Production: https://your-production-url.com/api
Development: http://localhost:8000/api
```

### Endpoints:

#### 1. Chat Endpoint
```http
POST /chatbot/chat/
Content-Type: application/json

{
  "message": "Book room A101 tomorrow at 2PM",
  "session_id": "uuid-string"
}

Response:
{
  "reply": "I've found Room A101 available tomorrow at 2PM. Would you like to confirm?",
  "intent": "book_room",
  "booking_data": {
    "room_number": "A101",
    "date": "2026-03-05",
    "start_time": "14:00",
    "end_time": "16:00",
    "status": "pending_confirmation"
  }
}
```

#### 2. Get Available Rooms
```http
GET /booking/rooms/available/
Query params: ?date=2026-03-05&start_time=14:00&end_time=16:00

Response:
{
  "rooms": [
    {
      "id": 1,
      "room_number": "A101",
      "capacity": 30,
      "building": "Engineering Building",
      "features": ["Projector", "Whiteboard"]
    }
  ]
}
